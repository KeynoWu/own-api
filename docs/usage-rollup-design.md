# 日志修剪不丢账 — 日账本与冷备 设计 v1.0（DR-17）

> 状态：**已实现（2026-09-20）**。守护断言：`test/e2e.ts` §18（R17-1…R17-9）、`test/hardening.ts`「UI 钉（DR-17）」与 v5 迁移回写两钉。
> 受众背景（全部取舍的前提）：单用户本机实例，请求日志是**内存环 + db.json 同体**，`logRetention` 默认 2000 条；
> 长会话 agent 流量一天就能打满。用户裁决：**保留上限不动**（热路径性能与库体积优先），但**数据要真实留下来**。
>
> **引用约定**：本文 DR-17-* 为本文私有编号；裸引 G21 指验收对比相关约定，AR-*/SPD-* 指 `docs/auto-routing-v2-design.md`。

## 1. 目标与非目标

**目标**：日志离开原始窗（被裁剪或被清空）时**先过账再丢**——折成一张极小的日账本，让「近 7 天 / 近 30 天」档变成真实数字；
同时把被裁原文追加进独立 JSONL 冷备，全保真可离线分析。存储有界：2000 条原始 + 每天 × 模型 × 渠道几行。

**明确非目标**（勿在实现中"顺手"加）：
1. **不存 prompt / 响应内容**——日志本就不存，账本与冷备同规（只有计数与链路元数据），这是隐私边界不是省事。
2. **不引入外部时序库**（Prometheus / SQLite / DuckDB 等）——桌面单机产品不背这个依赖；冷备 JSONL 已给出口子。
3. **不改 `logRetention` 默认值、不新增设置项**——设置面收敛（F5.3）与用户裁决双重约束。
4. **速度排行 / 号池健康 / auto 验收对比仍只看原始窗**——它们的语义是"当前健康/最近行为"，不是历史账；
   账本粒度（无 p50/p95、无 chainAttempts）也支撑不了它们，硬接会造出假精度。
5. **不做冷备的 UI 管理**（列表/下载/清理）——文件在数据目录，属于用户自己的数据。

## 2. 数据模型

`UsageRollup`（`src/types.ts`），折叠键 = **本地日 × 归因模型 × 渠道**：

| 字段 | 口径 |
|---|---|
| `day` | 本地时区 `YYYY-MM-DD`，取**日志自身 ts**（账记在"使用发生那天"，不记折账时刻） |
| `model` | 折叠时点的 `publicName \|\| requestedModel`——与 DR-14 统计归因同源 |
| `channel` | `channelName \|\| '-'` |
| `requests` / `errors` | 计数 |
| `pin` | **净新增输入** `Σ max(0, promptTokens − cr − cw)`——与 KPI / `computeCost` 同口径（缓存不双计） |
| `pout` / `cr` / `cw` / `costUsd` | 输出 / 缓存读 / 缓存写 / 成本 |
| `latSumMs` / `latN` | 平均延迟**原料**（和与样本数），不是均值——合并时才能精确加权 |

- 落盘：`db.json` 顶层 `rollups`（db 版本 v5）。
- 上限：`MAX_ROLLUPS = 6000` 行，超限按**最旧的天整体裁**（正常量级几年到不了；到顶说明维度异常膨胀，保最新）。
- 冷备：`<数据目录>/logs-archive-YYYYMM.jsonl`，按日志自身月份分文件，每行一条完整 `RequestLog`（0600）。

## 3. 时机与不变量

**DR-17-1｜原始日志离开内存的每条路径都必须先过账。** 目前两条：`pushLog` 超限裁剪、`clearLogs` 清空。
新增第三条路径时若忘了折账，长窗统计会与现实脱节——这是本设计的核心不变量。

**DR-17-2｜账本行与原始日志集不相交 → 合并统计不双计。** 一条日志要么在原始窗、要么在账本，不会同时在。
消费端（使用统计页）把两者拼起来聚合即为全量，见 §5。

**DR-17-3｜冷备尽力而为，不阻断主路径。** 写文件失败只 `console.warn`，请求照常返回、账本照常折。
冷备是旁路不是账——账在内存折好后随 `save()` 落盘。

**DR-17-4｜裁剪只由写入触发，缩窗本身不动数据。** 用户把 `logRetention` 调小后，日志在下一次 `pushLog` 才裁——
钉 R17-1 焊死这个时序（先见账后落盘的前提）。

## 4. 接口

- `GET /api/rollups`（admin）→ `{ rows: UsageRollup[] }`，按 `day` 升序。
- 配置组导出（`GET /api/config/export`）**不含** `rollups`——导出的是配置，不是账（与 logs 同规）。

## 5. 消费端合并（使用统计页）

被裁数据以**伪日志**形态进入前端聚合：`_n`（请求权重）/ `_e`（失败权重）/ `latencyMs` 存**和**（`latSumMs`）——
`groupAgg` 的 `latSum` 累加后除以合并请求数才是精确加权平均；`addAgg` 对 `_n`/`_e` 缺省视作 1，原始日志行为不变。

- 进聚合视图：KPI（真实消耗/请求数/成本/缓存）、使用趋势、Provider 统计、模型统计。
- **不进**「请求日志」明细表——账本行没有单条时间/状态/链路痕迹，混进去等于造假行。
- 模型下拉筛选**双匹配** `requestedModel === 选中值 || routedTo === 选中值`：DR-14 后统计按真实模型归因，
  筛选器同规才能"选中 Qwen3.8-Flash-Next 看它实际吃了多少"（此前 auto 流量全挂在 `model_auto` 名下，选中真名恒 0 条）。
- 保留上限横幅改口：达上限时说明"更早记录**已折进日账本**（明细不可查，KPI/趋势/统计仍完整）"，
  不再说"已被丢弃"——那是本设计之前的真相。

## 6. 迁移

db v4 → v5：仅新增 `rollups` 数组字段，补空即迁移完成；元素级清洗（`day` 需匹配 `YYYY-MM-DD`、
`model`/`channel` 为字符串、`requests` 为数字），坏行丢弃并 `warn`——与 agentLinks/routes 同规，
防坏行毒化统计合并。落盘版本号必须诚实回写（hardening 两钉）。

## 7. 已知边界

1. **存量救不回来**：上线前已被裁掉的日志没有账本，账从本版起记。
2. **明细随原始窗过期**：单条请求的 p50/p95、重试与链路痕迹（`chainAttempts`/`retries`）不进账本——聚合后无法还原，
   这是降采样的物理代价。
3. **账本只到"天 × 模型 × 渠道"**：同一天内的小时级曲线在明细过期后不可恢复（趋势图按天档仍准确）。
4. **冷备文件不自动清理**：长期运行需用户自行归档（每月几 MB 量级，含计数不含内容）。
