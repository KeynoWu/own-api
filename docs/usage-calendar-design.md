# 统计页日历区间查看 — 设计 v1.0（设计与验收标准）

> 状态：**设计。本文已按 2026-10-20 仓库实现逐条核对（设计 ↔ 实现一致）；"是否通过验收"以测试实跑为准，本文不声明已验证。**

## 0. 结论摘要（先结论）

1. **窗口收敛为两类**：**日历区间**（含日历快捷键）一律 **[from, to) 右开**，`from` = 起始本地日 00:00，
   `to` = 结束本地日次日 00:00；或**「今天」**（`[本地零点, now]`，`toIncl = true`，按小时，含当前部分桶）。
   滚动档（近 24 小时 / 近 7 天 / 近 30 天）已按 owner 决定移除（§5.5）；任何**未知/残留档位一律退化为「今天」**。
   第一原则是账本过窗必须与 P1-5 同规。
2. **数据源仍是前端合并，不是 `/api/stats`**：`src/usage.ts#buildStats` 不合并日账本，走它会丢掉 DR-17 的全部长窗收益。
3. **两档可用性必须如实分层**：热日志窗（有明细、小时粒度）与日账本（只有天粒度、无明细）合并渲染但**不相交、不双计**；
   账本伪日志只进 KPI/趋势/Provider/模型统计，**不进**「请求日志」明细表。
4. **账本过窗用「日区间相交」而非旧的「正午伪 ts 比下界」**：新谓词 `_d0 < to && nextDay(_d0) > from`（两端都判）；
   v0.1.17 的真实谓词是 `l.ts >= from`（伪 ts=正午、**只有下界**）。真实收益两件：① **补上上界**——旧式套在
   **过去的自定义窗**（如 `[T0−10d, T0−7d)`）会把窗**之后**直到今天的账本日一起拖进来；② 结果**与查询时刻无关**。
   滚动档移除后，两类窗口的 `from` **都是本地日零点**，账本行不可能"跨在窗前" ⇒ 旧「近 24 小时最多多算一天」的
   取舍**随之消失**；**「今天」与 v0.1.17「今天」档逐时点一致**（§4.5）。
5. **接口只做纯增量**：`GET /api/logs` 加可选 `from`/`to`（`from` 闭、`to` 开，畸形入参静默忽略不 500）；
   `GET /api/overview` 加 `oldestLogTs`/`newestLogTs`（无日志为 `null`）。两者都不改既有字段语义。
6. **不改 `buildStats`**：它的窗口是**闭区间** `l.ts >= from && l.ts <= to`，已被速度排行 / G21 验收对比等消费方依赖；
   本设计不改它，右开口径只落在新接口与前端聚合上（口径分叉见 §2.4）。
7. 冷备 `logs-archive-YYYYMM.jsonl`、环比、导出、自定义时区、多月并排、分钟级均**非目标**（§7）。

## 1. 背景与目标

**目标**：使用统计页（`web/index.html` 的「使用统计」视图）新增日历式查看：

- 月历网格点选：点一天 = 看该**单日**；已有单日时再点另一天 = 看该**区间**，自动归一 `start <= end`。
- 预设快捷键：今天 / 昨天 / 本周 / 本月 / 上月；下拉只保留「今天」（其他日期一律用日历选，§5.3/§5.5）。
- 有数据的日子做视觉区分；热窗明细与日账本**两者都没有**的日子灰显「无数据」。

**非目标在本节的界定**：本设计只扩展"窗口选择"，不扩展"能查什么"——可查的数据面仍是现有的两档（§3），
不新增第三档检索能力。

## 2. 现状核实（已按实现核对）

### 2.1 窗口来源：`statWin` 纯函数区

`web/index.html` 的统计视图内有一段**纯函数区**（`pad2` → `win`，不碰 DOM，供 hardening 抽真实源码块求值）：

- `dayKey / dayStartOf / nextDay / normDayRange / rangeLabel / monthGrid / statWin`。
- `nextDay` 用**日历进位**（`new Date(y, m, d+1)`）而非 `+86400e3`：跨月/跨年/夏令时都不错位。
- `statWin(ovSt, now)` 只剩**两个分支**：
  - `st.range` 存在 → **日历区间** `[from, to)`，`toIncl = false`，`custom = true`，
    `hourly = span <= 2 * 86400e3`，`label = rangeLabel(range)`；
  - 否则（含任何**未知/残留档位**，如升级前内存里的 `hours`）→ **「今天」** `[今天零点, now]`，`toIncl = true`，
    `hourly = true`，`label = '今天'`——不崩、不静默换成别的窗。
- 数字化滚动档（近 24 小时 / 近 7 天 / 近 30 天）分支**已删除**（§5.5）。

### 2.2 现有 `from`/`to` 状况（实现后）

- `GET /api/logs` 支持可选 `from`/`to`（`from` 闭、`to` 开）；空串/纯空白/`NaN`/`Infinity` 一律忽略，**不 500**。
- `GET /api/overview` 新增 `oldestLogTs`/`newestLogTs`（`store.db.logs` 的 min/max，空日志为 `null`）。
- 前端：**自定义区间**按窗取数 `/api/logs?limit=5000&from=…&to=…`；**预设档**保持 `/api/logs?limit=5000`。
- 原始日志过滤统一为 `allLogs.filter((l) => l.ts >= win.from && l.ts < win.to)`。

### 2.3 为什么前端聚合，而不是 `/api/stats`

- `src/usage.ts#buildStats` 只读 `store.db.logs`，**不读 `store.db.rollups`**。
  DR-17 §5 的合并逻辑（账本 → `_n` 伪日志 → 聚合）只实现于 `web/index.html`。
- 若统计页改走 `/api/stats`：日账本整档丢失 → 任何跨出热窗的日历区间（如点选的近 7 / 30 天）退化成"最近 2000 条"，
  与 v0.1.16 发布说明「长窗统计变真」直接相悖。
- 因此：**老区间与新日历区间都必须走前端合并口径**。`buildStats` 继续服务于速度排行、
  G21 验收对比等自身消费方，不作为统计页数据源。

### 2.4 必须声明的口径分叉

`buildStats` 的窗口是**闭区间**（`ts <= to`），自定义区间是**右开**（`ts < to`）。两者不一致，但**不打通**：

- 新 `/api/logs?from&to` 与前端聚合按 **[from, to)**；
- `buildStats` 保持闭区间不动，避免影响速度排行与 G21 对比；
- 边界差异只影响"恰好落在 `to` 这一点"的数据；前端取数走新接口，不存在同一份数字被两套口径各算一次。

## 3. 数据模型与三档可用性

| 档 | 载体 | 粒度 | 明细 | 上限 | 本期可用性 |
|---|---|---|---|---|---|
| 热日志窗 | `store.db.logs`（内存 + `db.json`） | 有 `ts`，**小时可分辨** | 有（单条状态/链路/延迟） | `logRetention` 默认 **2000**；前端最多取 **5000** 条 | **可用**（唯一明细来源） |
| 日账本 | `UsageRollup`，`本地日 × 归因模型 × 渠道` | **仅天** | 无 | `MAX_ROLLUPS = 6000` 行，超出按**最旧的天整体裁** | **可用**（只进聚合，不进明细） |
| 冷备 | `<数据目录>/logs-archive-YYYYMM.jsonl` | 完整原文 | 有 | 无应用内上限 | **不暴露**（§7 非目标） |

**账本行的前端形态**（`web/index.html#rollAll`）：

- `_d0` = 该本地日**零点**时间戳——用于**窗口过滤**与"是否账本行"判定；
- `ts = _d0 + 12h`（**正午**）——**只用于趋势桶归属**，不参与窗口过滤；
- `_n`（请求权重）/ `_e`（失败权重）；`latencyMs` 存 `latSumMs`（和，不是均值——`groupAgg` 累加后 ÷ 合并请求数才是精确加权平均）。

**不相交不变量（DR-17-2 的消费端表述）**：一条日志要么在热窗、要么已折进账本，不会同时在。
账本行来自**被裁掉的日志**，故 `原始日志 + 账本` 合并渲染是全量且**不双计**。

**分流规则**：账本伪日志进 KPI、使用趋势、Provider 统计、模型统计；**不进**「请求日志」明细表。

**保留上限横幅（F6，仅预设档）**两个分支（`web/index.html` 实现原文）：
① `logRetention <= 5000` 且已取满 → 「日志仅保留最近 N 条且已达上限——更早记录已折进日账本（明细不可查、KPI/趋势/统计仍完整）」；
② `logRetention > 5000` 时取数先撞 5000 → 「本页统计仅取最近 5000 条日志——更早记录未纳入（当前保留上限 N 条）」——
即 **"仍完整"只对"已被 retention 裁掉、已折进账本"的部分成立**；仍在保留上限内但未取回的部分并不完整（§8.15 同口径）。

## 4. 窗口口径（第一原则）

### 4.1 两类窗口

- **日历区间（含日历快捷键）**：**[from, to) 右开**。`from` = 起始本地日 **00:00**；
  `to` = 结束本地日**次日 00:00**；`toIncl = false`。
- **预设档「今天」**（本文其余处简称"预设档"）：`from` = 本地日 **00:00**、`to = now`，`toIncl = true`
  （桶铺到当前桶，含 `now` 所在的部分桶）。这是 v0.1.17「今天」档的既有语义，本设计不动它。
- **两类窗口的 `from` 都是本地日零点**——这是滚动档移除后成立的不变量（§4.5-5）。
- 用户可见文案是"含首尾"（如 `01-30 ~ 02-02 · 4 天`），接口是右开——**同一件事的两种表述**：
  `接口 to = 文案末日 + 1 天 00:00`。

### 4.2 粒度判据

- **自定义区间**：令 `span = to - from`，**`span <= 2 * 86400e3` → 按小时；否则按天**。
  用区间长度而不是"数自然日"，消掉"含头含尾"的计数歧义。例：单日 `span = 1 天` → 小时档；
  恰好 2 天 → 仍小时档（阈值边界含）；3 个自然日 → 天档。
- **预设档「今天」**：固定按小时（`hourly = true`）；其 `span < 1 天`，与上面的判据自洽。

### 4.3 趋势桶

- 桶起点 = `from`（已按粒度对齐）；桶集合：
  - 自定义区间：`t` 从 `from` **到 `to` 不含 `to`**（`toIncl = false`）；
  - 预设档「今天」：`t` 从起点**到 `to` 含 `to`**（`toIncl = true`，最后一个桶是当前部分桶）。
- **天档按本地日历日推进**（`nextBucket`：`new Date(y, m, d+1)`），**不走固定 `86400e3`**：
  夏令时当天是 23 或 25 小时，固定毫秒步进会让桶跨日错位。小时档用固定 `3600e3` 无此问题。

### 4.4 与既有权裁的关系（本功能的第一原则）

- **DR-17**：引入日账本，被裁日志先过账再丢；账本与原始窗不相交，消费端合并渲染不双计（R17-5 焊死互补性）。
- **P1-5（v0.1.17 修复）**：账本行此前只过滤模型不过滤时间窗，导致「今天」档把建库以来全部历史账算进 KPI
  （现象："图对、头部数字离谱"）。修复口径 = `rollLogs` 与 `logs` 同过时间窗。
- **本功能的关系**：只是把"窗口"从 4 个预设扩展为任意区间，**不改变 P1-5 的过滤义务**；
  并进一步把过窗谓词从"正午伪 ts 比下界（仅下界）"改为"日区间相交（两端都判）"（§4.5）。

### 4.5 日粒度近似（实现口径）

账本只有"天"。窗口归属的最终谓词（`web/index.html#rollLogs`）：

```js
const rollLogs = rollAll.filter((l) => l._d0 < win.to && nextDay(l._d0) > win.from);
```

即：**账本行 r 计入 ⟺ 其本地日区间 `[_d0, nextDay(_d0))` 与 `[win.from, win.to)` 交集非空**；一旦相交，**按整天计入**。

后果与实现取舍：

1. **选「某一天」D**：`[D 00:00, D+1 00:00)` 与当天日区间完全重合 → 当天账本整天计入。
   若该日实际只做了半天，账本无法区分半天，**这半天会被当成一整天**——降采样的物理代价（DR-17 §7.3），不是本功能引入的误差。
2. **预设档「今天」`to = now`**：`to` 不是日界，按同一谓词，**当天账本整天计入**。
3. **相对 v0.1.17 的真实收益**：
   - v0.1.17 的真实谓词是 `rollAll.filter((l) => l.ts >= win.from)`——伪 ts=正午、**只有下界**。
     新式两端都判，收益是：① **补上上界**——旧式"仅下界"若套在**过去的自定义窗**（如 `[T0−10d, T0−7d)`）上，
     会把窗**之后**直到今天的账本日全部拖进 KPI；② 结果**与查询时刻无关**。
   - **「今天」档与 v0.1.17「今天」档逐时点一致**（旧式 `ts >= 今天零点` 只命中今天正午，新式日区间相交也只命中今天）。
   - **旧实现并没有"上午查『今天』会漏当天已折账部分"**：它只有下界、无上界，`from = 今天零点` 时正午必然 `>= from`，不会漏。
     此前把"正午落不进 `[from,to)`"说成既成事实是错的；那只是**若改成单点 ts 比较**才会出现的假设性问题（见下条）。
   - **窗口解析**（from/to 取值、粒度、文案）与 v0.1.17 的「今天」档**同形**；变化只在过窗谓词本身。
4. **假设性讨论（不是 v0.1.17 的既有行为）**：若用单点 `ts(正午) >= from && ts < to` 去过窗，则"今天"档在**上午**查询时
   `正午 >= now = to` → 当天账本被排除、KPI **少计**当天已折账部分，且同一档位上午/下午结果不一致。
   日区间相交消除了这个**时段依赖**；hardening 用"半天窗"（`to` 早于正午，`[今天零点, +6h)`）**确定性地**复现该形状，
   不依赖跑测试的时刻。
5. **不变量：两类窗口的 `from` 都是本地日零点 ⇒ 账本行不会"跨在窗前"**。滚动档（近 24 小时）曾因窗起点落在
   昨天整点而可能把昨天整天计入；该档移除后此取舍消失，故也**不再需要"多计"横幅**（原 `rollPartial` 随档位一并移除，§5.5）。
6. **图与数的差额显式交代（`ledgerOff`）**：账本行按日过窗（计入 KPI/统计表），但若它的**正午落不进任何桶**
   （如上午查"今天"时正午桶尚不存在），趋势会 `ledgerOff++` 并在图下提示：
   **「另有 N 天已折进日账本（日粒度，无法定位到小时桶）——已计入上方 KPI 与统计表」**（§5.4）。

## 5. UI 交互与状态机

### 5.1 点选状态机（实现口径）

状态存 `ovSt.cal`（`{ open, month, start }`）与 `ovSt.range`（会话内存；刷新页回默认）。

| `start` | 点击日 `D` | 结果 |
|---|---|---|
| `null` | 点 `D` | `start = D`；`range = { from: D, to: nextDay(D) }` → **立刻按单日查看** |
| 非 `null` | 点 `D'` | `range = normDayRange(start, D')`；`start = null` → **区间完成**（含 `D' === start` 时退化为单日） |

- `normDayRange(a, b)`：`from = min(dayStart(a), dayStart(b))`，`to = nextDay(max(...))`——**反着点也归一**，不产生 `from > to`。
- **"再点重置"**：区间完成后 `start` 已是 `null`，再点任一天即进入下一轮单日 → 与"未选→单选→区间→再点重置"一致。
- **重复点同一天**：在 `start` 非空时点同一天 → `normDayRange(start, start)` = 单日，`start` 归零。
  即"幂等确认"，**不是取消**；取消走「清除」按钮（`range = null; start = null`）或下拉切档。
- 其他控件：`‹ / ›` 切月（`start = null`，`range` 保留）、「回到今天」、「完成」（收起日历）、
  下拉在自定义区间生效时多一个 `custom` 档显示区间文案（选中它本身不切档，避免误清区间）。

### 5.2 数据可用性四态（`dayInfo`，命名与代码一致）

| kind | 判定 | 视觉 | 悬停标题 |
|---|---|---|---|
| `raw` | 该日有**已加载**的原始明细（`rawDays` 命中） | 加粗（`n > 0`）；`n = 原始条数 + 该日账本请求数` | `YYYY-MM-DD：N 次请求` |
| `roll` | 无原始明细，但账本行 `day === 该日` | 斜体 + 淡显（`opacity .75`）；`n` = 账本请求数 | `…：N 次请求（仅日账本，无明细）` |
| `span` | 在热窗跨度内但明细未加载（`rawA != null && start <= rawB && nextDay(start) > rawA`） | 中性（`opacity .6`） | `…：在热日志窗内，明细未加载` |
| `none` | 与热窗/账本都不相交 | 灰字 | `…：无数据（更早，已超出可查范围）` |

- 输入：已加载日志 `allLogs`、账本行、`o.oldestLogTs`/`o.newestLogTs`。
- `span` 的作用：`logRetention > 5000` 时热窗内较旧日期可能不在本次取数里，**不谎称"无数据"**。
- 卡内图例（实现原文）：「加粗=当天有原始明细 · 斜体=仅日账本（无明细，数字仍完整） · 灰字=已超出可查范围 ·
  边框=今天。日期一律按本机时区；日账本为日粒度，选单日时该日账本按整天计入。」

### 5.3 预设快捷键与窗口

**日历快捷键**（`calCard` 的 quick 行，均为日对齐自定义区间 `[start 00:00, end+1天 00:00)`，走右开路径）：

| 档 | `from` | `to` |
|---|---|---|
| 今天 | 今天 00:00 | 次日 00:00 |
| 昨天 | 昨天 00:00 | 今天 00:00 |
| 本周 | 本周一 00:00（ISO 周一为首日） | 次日 00:00 |
| 本月 | 本月 1 日 00:00 | 次日 00:00 |
| 上月 | 上月 1 日 00:00 | 本月 1 日 00:00 |

**工具栏下拉**：只保留**「今天」**；日历区间生效时下拉里以 `custom` 档显示区间文案（选中它本身不切档，避免误清区间）。
其他日期一律用日历选——滚动档已按 owner 决定移除（§5.5）；原来「近 7 天 / 近 30 天」快捷键与下拉**同名却不同窗**的问题
随之消失（知道这段历史即可，不必再对照两套窗口）。

### 5.4 文案与提示

- `rangeLabel`（实现口径）：
  - 单日（首尾同日）→ `MM-DD`（如 `10-18`）；
  - **同年**区间 → `MM-DD ~ MM-DD · N 天`（如 `01-30 ~ 02-02 · 4 天`）；
  - **跨年**区间 → `YYYY-MM-DD ~ YYYY-MM-DD · N 天`（如 `2025-12-30 ~ 2026-01-02 · 4 天`）。
  - 规则：**同年两端都省年份，跨年两端都带年份**——不许一侧带一侧不带。`N` = 含首尾的自然日数。
- 区间提示条（仅自定义区间，`win.custom`）：
  - 有仅账本日 → **「有 N 天仅有日账本，明细不可查（KPI/趋势/统计仍完整）」**（仅就这些**只有账本**的日子而言）；
  - 有完全无数据日 → **「有 N 天已超出可查范围（账本也已裁剪，该日统计缺失）」**；
  - 两者都有时用 `；` 连接。
- **截断横幅（自定义区间）**：见 §8.15；与预设档 F6 横幅两口径不混用。
- 图/数差额（`ledgerOff`）：见 §4.5-6。
- 保留上限横幅（F6）：**只在预设档出现**（`!win.custom`）；自定义区间走 §8.15 的精确判据。

### 5.5 为什么不做滚动档（设计决定，记录 owner 决定）

owner 决定原话：**去掉「近 24 小时 / 近 7 天 / 近 30 天」这类选项，只保留「今天」；用户要看其他日期就用日历查。**
记录原因，避免后人误以为漏做：

1. **同名档两套窗口**：下拉的「近 7 天 / 近 30 天」是**滚动窗**（`to = now`；`168h`/`720h` 从 `now − 168h/720h`
   再归零到日界，实际可能覆盖 **8 / 31 个自然日**），日历快捷键是**自然日窗**（含今天 7 / 30 天）；
   同一视图里两个**同名控件给出不同 KPI**。
2. **收敛后窗口只剩两类**，且两类 `from` 都是本地日零点——账本「日粒度最多多算一天」的取舍随之消失（§4.5-5），
   也不必再维护"多计"横幅。
3. **代价**：不能再一键看"最近 7 / 30 天"；但日历已有 本周 / 本月 / 上月 快捷键 + 任意点选区间，
   覆盖同样的需求面，且**窗口所见即所得**（选中的格子就是算进去的日子）。
4. **兼容**：任何残留/未知档位（升级前内存里的 `hours`）一律退化为「今天」，不崩、不静默换窗（§2.1）。

## 6. 接口契约

### 6.1 `GET /api/logs` 增加可选 `from` / `to`

- 入参：`from`、`to` 为 epoch 毫秒字符串，**均可选**；与既有 `limit` / `errors` / `model` 正交组合。
- 语义：给定 `from`/`to` 时，取 `l.ts >= from && l.ts < to`（**`from` 闭、`to` 开**）。
  **缺省某侧即不施加该侧边界**（保持既有行为），不做隐式 `now` 补全。
- 归一：空串 / 纯空白 / 非数字 / `NaN` / `Infinity` → **忽略该参数**，**不返回 400/500**。
- `from >= to` → `[from, to)` 为空集，**返回空数组**（不交换、不报错）。交换是**前端**归一的职责（`normDayRange`）。
- `limit` 仍作用于过滤后的结果（`slice(-limit).reverse()`，最新在前）。
- 响应体形状**不变**（仍为 `RequestLog[]`），纯增量，无破坏性变更。
- `GET /api/logs/stream`（SSE 实时尾）**不受** `from`/`to` 影响。

### 6.2 `GET /api/overview` 增加 `oldestLogTs` / `newestLogTs`

- 纯新增字段，**不改既有字段**。
- 取 `store.db.logs` 的 min/max `ts`；**无日志时为 `null`**（不是 0——0 会被误当 1970 年）。
- 用途：月历"该日是否完全在热窗之外"（`span`/`none` 判定）与"区间完全在热窗外"的提示；不用于逐日明细计数。

## 7. 非目标

1. **不做环比 / 对比上一周期**——需要第二套窗口与口径，且会诱导对日账本近似做不可靠比较。
2. **不做冷备 JSONL 检索**：`logs-archive-YYYYMM.jsonl` 是离线出口，不进 UI（延续 DR-17 §1 非目标 5）。
3. **不做自定义时区**：一律浏览器本地时区；跨时区一致性问题列入局限（§10）。
4. **不做导出**（CSV/JSON 下载）——与"导出的是配置不是账"同规，导出使用面另立设计。
5. **不做多月并排**：月历一次渲染一个月，跨月区间通过切月查看，不做双月/年视图。
6. **不做分钟级粒度**：最细到小时档；账本本身只有天粒度，分钟级只会造出假精度。
7. **不改 `logRetention` 默认值与上界**（延续 DR-17 §1 非目标 3）。
8. **不改 `buildStats` 的窗口语义**（闭区间），不给 `/api/stats` 加账本合并——会波及速度排行与 G21 对比。
9. **不把账本伪日志混入「请求日志」明细表**（DR-17 §5 硬约束）。
10. **不新增落库字段/索引**：月历可用性由 `overview` 的窗口端点 + 已取日志 + 账本行派生，不给 `db.json` 加状态。
11. **不做滚动档（近 N 小时/天快速窗）**：已按 owner 决定移除，改由日历选择（原因见 §5.5）。

## 8. 边界情形与期望行为（已按实现核对）

| # | 情形 | 期望行为 |
|---|---|---|
| 8.1 | **跨月**（如 1/31 → 2/2） | 归一后 `from = 1/31 00:00`、`to = 2/3 00:00`；月历显示锚点所在月，另一月由切月查看（不并排）；天档 3 桶。 |
| 8.2 | **跨年**（12/30 → 1/2） | `to = 次年 1/3 00:00`；文案两端都带年份；`nextDay` 日历进位，桶不因年份错位。 |
| 8.3 | **闰年 2 月与月历网格** | 天数取自 `new Date(y, m+1, 0).getDate()`，**不硬编码 28**：2026-02 = 28 天、2024-02 = 29 天，格数均为 7 的倍数；首格 = 当月 1 日所在周的**周一**；**跨月用相邻月日期补位**（`inMonth: false`，淡显 `opacity .4`），不是空白格；补位格**可点**（选中该日并切到它所在月）。 |
| 8.4 | **单日** | `start` 空时点 `D` → `[D 00:00, D+1 00:00)`；`span = 1 天` → 小时档，恰 24 个小时桶（首桶 `D 00:00`、末桶 `D 23:00`，不含次日零点）。 |
| 8.5 | **同一天重复点选** | `start` 非空时点同一天 → `normDayRange(start, start)` = 单日、`start` 归零（**幂等确认，不取消**）；区间完成后点任一天 → 开始新一轮单日。 |
| 8.6 | **未来日期** | `ts > 今天零点` 的格子 `disabled` + `cursor:not-allowed` + 标题「未来日期（不可选）」，点击不触发（避免 `[from,to)` 含未来空桶）。 |
| 8.7 | **`from > to`** | 前端 `normDayRange` 天然归一（`min/max`）；接口收到 `from >= to` 返回**空数组**，不交换、不报错。 |
| 8.8 | **无数据日期** | **允许点选**（否则无法回答"这天是不是真的没量"）；点后 KPI = 0、趋势空桶、明细「暂无数据」，月历该日按 `none` 灰显。 |
| 8.9 | **区间完全在热窗之外** | 早于 `oldestLogTs` 时无明细；若有账本则只呈现账本聚合（`roll`）；若连同账本也没有（早于建账本，DR-17 §7.1 存量救不回来）→ 提示「有 N 天已超出可查范围（账本也已裁剪，该日统计缺失）」，这是事实不是 bug。 |
| 8.10 | **区间跨越热窗边界** | 部分日 `raw`、部分 `roll`：KPI/趋势 = 明细 + 账本按日合并（不双计），**完整**（前提是本次取数未被 5000 上限截断，见 §8.15）；明细表只含明细部分；提示条挂"仅日账本"文案（§5.4）。 |
| 8.11 | **区间极长**（如整年） | 天档桶数 = 区间天数（可达 300+）；本版**不做下采样**（下采样 = 新口径，非目标），如实渲染并标注粒度。 |
| 8.12 | **`to` 非日界（预设档「今天」）** | `from` = 本地日零点、`to = now`（`toIncl = true`）：账本按日区间相交 → **当天整天计入**（§4.5）；趋势末桶为当前部分桶；正午落不进桶时 `ledgerOff` 显式交代（§5.4）。`from` 是日界 ⇒ 不存在"账本跨在窗前"，无需多计提示。 |
| 8.13 | **夏令时切换日**（本地时区） | 天档按 `nextBucket` 日历日推进，DST 日 23/25 小时不错桶；小时档固定 `3600e3`，跳变处可能少/多一个桶，按本地时间如实显示。 |
| 8.14 | **浏览器时区 ≠ 后端本地时区**（LAN 远程访问） | 账本 `day` 与后端 `localDay` 用**服务端**本地时区，前端窗口用**浏览器**本地时区；单机同机一致，跨时区客户端下日界可能错位 → 列入局限（§10）。 |
| 8.15 | **宽自定义区间 > 5000 条明细** | 自定义区间取数用 `limit = LOG_LIMIT + 1`（5001），判据 **`logTruncated(arr, win) = win.custom && arr.length > LOG_LIMIT`**——多取一条才能把"恰好 5000、一条没少"与">5000、真被裁"分开（旧式"取满且末元素晚于窗起点"在恰好 5000 时**误报**，已弃用）。命中即挂横幅：「所选区间明细超过 5000 条，仅取回最近 5000 条：更早的明细未纳入——已被裁剪的部分已折进日账本（KPI/趋势仍含），仍在保留上限内的部分两边都不在（KPI/趋势会少计）；缩小范围可看全。」→ **"仍完整"只对被裁部分成立**：仍在 `logRetention` 内、只是超出 5000 取数的明细，既不在返回也不在账本，**会少计**（默认 `retention = 2000 < 5000` 不触发；`retention > 5000` 的用户会撞上）。 |

## 9. 验收钉（按钉的类型，均为仓库中已存在的钉）

> 不编造钉编号与结论。钉姿态要求 **抽真实源码块求值**（`new Function` 跑真实代码），
> 而非 `includes()` 源码字符串空钉（audit §六 D-12/13/14 的教训：空钉让 P1-5 两个窗口缺陷全绿穿透）。

**类型 A — `test/hardening.ts`：抽真实源码块求值（DR-UC-1 / P1-5 系列）**

抽四段真实源码求值：① 纯函数区（`pad2` → `win`）② 过窗（`logs` / `rollLogs` / `aggLogs`）③ 可用性（`dayInfo`）
④ 趋势桶铺法（`buckets` / `ledgerOff` / `logTruncated`）；另用记录型 `el()` 跑页面里**真实的 `calCard`**（含真实 `dayInfo`）
做渲染级断言。该钉块实跑 **41 条**（其中渲染级 8 条）。覆盖：

| 覆盖点 | 断言要点 |
|---|---|
| A1 窗口解析 | 预设档「今天」= `[本地零点, now]`、`toIncl = true`、按小时、文案「今天」；**任何残留/未知档位（如 `hours` 数字）一律退化为「今天」**——不崩、也不静默换成别的窗。 |
| A2 区间归一与文案 | 自定义单日 = `[当日零点, 次日零点)` 右开、按小时、文案 `MM-DD`；3 天按天且标 `N 天`、恰好 2 天仍按小时；反着点归一为 `[早, 晚+1天)`；同年跨月只写 `MM-DD`、跨年必须带年份。 |
| A3 次日零点进位 | 闰年 2/28→2/29、2/29→3/1、跨年 12/31→1/1（证明不是 `+86400e3`）。 |
| A4 月历网格 | 2026-02=28 / 2024-02=29、格数为 7 的倍数、首格 = 当月 1 日所在周周一（跨月补位占位）。 |
| A5 账本日区间相交 | 「今天」只含**今日**账本、模型筛选在账本上生效、空账本零崩溃；**过去的自定义窗 `[T0−10d, T0−7d)` 只纳入相交的三天**（旧的"仅下界"谓词会红——它会把窗后的账本日也拖进来）；**半天窗（`to` 早于正午）仍纳入当天账本行**；开场即「今天」时昨日账本不进窗。 |

| A9 截断判据 | `logTruncated`：取回 > 5000（多取一条）= 真截断；**恰好 5000 / 未取满 / 预设档 = 不误报**（共 3 条）。 |

## 10. 局限与未验证面（如实声明）

1. **未做真实浏览器交互验证**：月历点选、悬停 tooltip、键盘可达性、响应式布局均未在真实浏览器中验证；
   本文给出的是期望行为与钉型（渲染级钉用记录型 `el()` 覆盖组装路径，不等于真实 DOM 行为）。
2. **未做性能测量**：长区间（如 365 天、300+ 桶）的趋势 SVG 渲染耗时、悬停命中计算未测量；本文不声称任何性能数字。
3. **日粒度近似的误差未量化**：账本按整天计入对"半天使用"的高估幅度取决于当日折账时点分布，本文不给出百分比。
   滚动档移除后**不再有"窗起点非日界"导致的额外多算**（两类窗口 `from` 都是本地日零点，§4.5-5）。
4. **自定义区间截断：判据本身精确，残留限制两点**（§8.15）：判据 `win.custom && arr.length > LOG_LIMIT` 依赖
   `/api/logs?limit=LOG_LIMIT+1` 多取一条，因此依赖该接口「最新在前、取最近 `limit` 条」的排序契约——契约变了判据会失真
   （已有 3 条硬化钉锁住：真截断、恰好 5000 不误报、未取满/预设档不适用）。第二点：横幅只说"超过 5000 条"，
   **不声称具体缺了多少条**。另需与"完整性"分开看：账本只收**被 retention 裁掉**的日志，宽区间里**仍在保留上限内、
   只是超出 5000 取数**的明细两边都不在，**KPI/趋势会少计**（默认 `retention = 2000 < 5000` 不触发，
   `retention > 5000` 的用户会撞上）——这不是"统计仍完整"，横幅已按两种情况分开措辞。
5. **跨时区客户端未验证**：浏览器时区与后端时区不一致时（§8.14）日界错位的实际表现未测。
6. **DST 边缘未验证**：§8.13 的日历日推进方案在真实 DST 时区未经验证（本机时区通常无 DST）。
7. **账本裁剪的既有边界**：`MAX_ROLLUPS` 超限裁剪与 C-02（单日行数超限可能裁掉唯一那天）是 DR-17 的已知面，
   本功能只消费账本、不改变该行为，故不因此免除其影响。
8. **实现状态**：本文已按 2026-10-20 仓库实现逐条核对；此后代码若再变动，以仓库当前代码与测试为准。
