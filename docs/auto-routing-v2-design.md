# auto 路由 v2 设计：三信号正交（健康 / 饱和 / 速度）+ 视觉能力

> 状态：设计稿 v2.2（2026-09-15 自审修订 R1-R10 + 六镜自查 F1-F6）
> 复核状态：R1-R10 为单人自审；F 系列为六视角自查（并发/语义/统计/产品/测试/安全）。多智能体评审团因基础设施故障未跑成，通道恢复后应补一轮独立交叉验证（见 §9）。
> 前置：speed-insights v1.1（DR-SI 系列）已提供 TTFT/吞吐采样与单源基准
> 本文决策编号 AR-xx、修订编号 R-xx/F-xx；沿用既有回归钉（C3/C10/C11/C12/N10/§8-4/N11）

## 0. 设计主张

一句话：**健康分（坏没坏）、饱和态（忙不忙）、速度因子（快不快）是三个正交信号，各自独立窗口与状态机，最终在权重处相乘。**

v1 的问题：健康分一个信号被迫回答三个问题，答案是哪个都答不好——
- 慢但从不失败的候选 health≡1.0（"绕开慢的"宣传只有一半是真的）；
- 429 配额耗尽的候选 10 分钟后满血复活，每个窗口白烧一次失败请求；
- 粘性只看成功率，粘住一个首包劣化 5 倍的候选照样粘。

## 1. 挂：失败分类学（AR-1）

以两问过滤所有失败：**换候选能解决吗？**（错在候选还是请求）× **该惩罚健康吗？**（还会再犯吗）

| 格 | 判定 | 健康样本 | 处置 | 现状 |
| --- | --- | --- | --- | --- |
| A 候选真故障 | 错在候选，会再犯 | 记败 | 换候选/换 key 续链 | ✓（5xx/超时/连接拒绝/404 模型名） |
| B 候选暂时饱和 | 错在候选，**但会很快自愈** | **不记**（10min 窗会把尖峰错杀成长期劣化） | **饱和态**（§2） | 429 现仅换 key/候选 |
| C 请求×候选不匹配 | 候选没错 | 不记（sample:false） | 换候选续链 | ✓（超窗 C10 / 协议软过滤 / 视觉 §4） |
| D 请求本身坏 | 换谁都没用 | 不记 | 短接全链透传 | ✓（其它 4xx） |
| E 客户端取消 | — | 不记 | 双向剔除 | ✓（499 §8-4） |

**AR-2（A 格边角）**：渠道号池内所有 key 均鉴权失败（401/403）→ 这是渠道级真故障，对候选记**一次**健康败样本（现仅透传不记）；单 key 失败仍只走号池冷却，不记。

**AR-3（C 格边角）**：全候选均超窗时，最终报错聚合为「所有候选窗口不足（最大 N tokens）」，不再透传最后一个候选的原始报错；chainAttempts 明细保留。

**F2.1（新增，D 格例外）**：**带图请求的 400 不适用 D 格短接**——请求含图时，任何 400 都按 C 格处理（候选可能只是不支持视觉，链继续），判定顺序固定为：超窗（C10）→ 视觉学习（§4）→ 其它 400（仍按 C 格换候选，不短接）。

## 2. 饱和态 saturation（AR-4，新增状态机）

- **触发（R1 修订 + F1.2 窗口定义）**：需满足其一，防单次尖峰误杀——
  (a) 该候选号池**所有可用 key** 在链内均 429（key 级冷却先行且已耗尽）；
  (b) **60s 滑动窗**内对同一候选**跨 key 累计 ≥2 次** 429（不以链为作用域——每链重置会让两链各 1 次永不升级）。
  单次 429 且换 key 成功 → 只走号池冷却，不触发候选饱和（避免与 key 级冷却双重惩罚）。
- 状态：`saturatedUntil: Map<routeId, until>`；时长 `min(base × 2^n, cap)`，`base=60s`、`cap=1800s`、n=该候选连续饱和次数。
- **retry-after 优先（F4.3）**：上游显式给出 retry-after 时取 `max(retryAfter, 退避值)` 且**不受 cap 约束**——渠道日配额烧完就该饱和到明天，1.8 万秒的 cap 不该挡住"明天才恢复"。头解析容错：非数字/为 0 视同未给。
- **清零**：只可能发生在全饱和回退路径（唯一会试饱和候选的路径）试出成功时。
- **生命周期（R5）**：进程内存态，与健康/粘性同生命周期，不持久化。
- 效果：饱和候选**移出存活集**（不参与首选与续链）；**若存活集因此为空** → **不做必败请求（R2）**：直接返回 429 + `retry-after = min(saturatedUntil) - now`，对齐 HTTP 语义由客户端重试。例外：某候选剩余饱和期 < 5s 且链预算充裕 → 仍试它（贴脸醒来不值得让用户多等一轮）。
- **顶层报错可区分（F2.2）**：合成 429 的 message 固定为「所有候选饱和（最早 Xs 后恢复）」，与上游透传 429 区分；chainAttempts 照常带明细。
- **与粘性（F1.1 修订）**：粘性目标饱和 → 本轮绕行不删绑定，**且绕行轮照常滑动续期 TTL 并打 degraded 标**——否则 30min 长饱和会静默耗尽 10min 的绑定 TTL，恢复后缓存亲和无声断裂。degraded 绑定在目标恢复后自动转正，无需人工干预。
- 与健康的分工：健康只回答"坏没坏"；饱和只回答"现在忙不忙"。429 永远不进健康窗（C11 不变）。
- **样本污染防护（F6.1）**：健康样本按 `(routeId, vkey)` 限频——每 vkey 每候选每分钟至多 1 个样本，封顶"定向刷失败拉低候选"的污染速度（vkey 持有者无法选候选，只能靠内容触发上游 5xx 慢速污染）。
- 观测（R8 补全）：`/auto-health` 增 `saturatedUntil / speedFactor / ownTTFTP50 / ownThroughputP50 / bench`；管理台号池健康页展示饱和剩余秒数与速度因子。
- 开放问题：503 且带 retry-after 是否同样进饱和态？v1 暂不（保持 429 单一触发源），观察一个版本。

## 3. 速度因子 speedFactor（AR-5）

**测什么（R3 修订——指标分工，纠正可比性污染）**：
- **权重层用 decode 吞吐**：`completionTokens / 生成耗时`，与输入输出长度基本无关——最公平的跨候选指标。端到端时延是陷阱：话痨模型、接长文档的候选、吃缓存的候选（prefill 短 → TTFT 天然好看）都会被系统性误判。
- **粘性降级判据用 TTFT**：它才是用户体感（等首包）。粘性目标是"这个用户此刻的体验"，允许有偏。
- **两个指标、两个基准，不混用**（实现时不得共用一个字段）。
- 样本随 `recordAttempt` 顺带采集（gateway 已有 ttftMs / latencyMs / completionTokens）。
- **非流式口径（F3.3）**：非流式无首包，吞吐 = `completionTokens / 总时延`——含 prefill 污染，是下界近似；文档标注该误差，跨流式/非流式不互比。

**跟谁比**：相对基准，不用绝对阈值（50k 上下文 prefill 慢是物理性的）。
- 基准 = 全候选同指标 p50 的中位数（DR-SI-9 同源思想），auto.ts 内部轻量维护，**5s 计算缓存**（不逐请求扫全量）。
- `speedFactor = clamp(bench / own_p50, 0.5, 2)`——**clamp 必须有**：否则一个快候选垄断全部流量。
- **样本窗与平滑（R3 + F3.1/F3.4）**：速度窗 **1h**（慢不需要秒级反应，与健康的 10min 窗刻意不同）+ **EMA（α=0.3）**。样本滚出窗口时**不做硬重置**：沿用上一次有效因子、按 1h 半衰期指数衰减回 1——否则低权重候选陷入"流量少→样本滚出→factor 硬回 1→流量回流→样本变差→再降权"的约 1h 周期振荡。
- **样本上限（F1.4）**：速度样本同款环形上限（MAX_SPEED_SAMPLES=256/候选），与健康窗对齐。
- 冷启动（速度样本 <3）：factor = 1.0，与 health 冷启动口径一致。

**怎么用（三个注入点，强度递增）**：
1. **权重层**（P2）：并入统一有效权重（§5 R4）——慢候选软降权，流量自然漂移，不剔除。
2. **粘性层**（P2）：粘性保持条件从 `health ≥ 0.4` 扩为 `health ≥ 0.4 且 TTFT_p50 < 3 × TTFT基准`；降粘后重粘需 `< 2 ×`——与 C3 同构的迟滞带（3×/2×）。**此处的 p50/基准是 TTFT 口径（R3 分工），与权重层的吞吐因子互不引用。**
3. **对冲层**（并入 AR-5，**明确暂缓**）：TTFT 超阈值向第二候选发对冲请求，先首包者胜。计费语义（对冲请求可能双边计费）未想清前不做，仅留接口位。

## 4. 视觉能力三态（AR-6，新增）

**问题**：加路由要不要人工标注多模态？纯自动识别不可靠（OpenAI/Anthropic `/models` 均无能力字段；模型名启发式对内部部署模型失灵；主动探测花钱且部分网关静默丢图返回 200，探测结果反而造假）。纯手动又违背"开箱即用"。

**方案：三态标注 + 启发式初值 + 被动降级学习。**

- 路由 schema 增 `supportsVision?: boolean` 三态：`true / false / unknown`（unknown ≠ 支持，只是没证据）。
- **启发式初值**：从上游导入模型时按已知多模态家族静态表（gpt-4o/4.1、o 系列、claude-3+、gemini、glm-4v、qwen-vl、llava、llama-3.2-vision…）置 `true`，其余 `unknown`；表只做先验，可配置关闭。
- **① 硬过滤扩展**：请求含图片块（OpenAI `image_url` / Anthropic image）且候选 `supportsVision === false` → 软排除（与 tools/流式同语义：绕行不改写粘性）。`unknown` → 放行，交给学习闭环兜底。
- **可选加权**（实现细节，默认开）：带图请求时 `unknown` 候选的 visionBias=0.25（§5 统一权重），非排除——尽量不付"第一次失败"的学费。
- **被动降级学习（关键闭环，R6 收窄前提 + F6.2 门槛）**：仅当「请求确实含图 + 上游 400 + 报错命中**保守**模式列表 + **同候选 60s 内 ≥2 次独立链命中**」四者齐备才触发 → 自动置 `false` 并持久化、日志记一条、链继续（C 格语义：候选没错，不记健康样本）。**用户手动改过的路由学习不再覆盖**——人的标注永远赢；学习所得标记在管理台可**一键重置回 unknown**（防上游升级支持视觉后永久错标，也防损坏图片误学）。
- **判定顺序（F2.1）**：带图 400 的处理次序固定：超窗（C10）→ 视觉学习 → 按 C 格换候选。视觉永不与 C10/D 格双重判定。
- **管理台可见**：路由行展示视觉 ✓ / ✗ / 未知，可手动修改。
- **配额精度顺带修（R7 补坑）**：带图请求的 `inputEst` 计入图片 token——data URL 可解析出 w×h 精算（≈(w×h)/750）；**http URL 不为计费去下载图片**，用保守常数（1000 tokens/图）。现状图片请求预占偏低，限额用户被低估占用。
- **不做**：音频/PDF 独立字段（转换层 audio 已丢弃+告警；PDF 留接口）；主动探测请求。

## 5. 决策管线 v2

**R4 统一：全系统唯一有效权重公式**（首选随机、续链降序、unknown 后置共用一处实现）：

```
effectiveWeight = weight × health × speedFactor × visionBias
                  （visionBias：带图请求 unknown=0.25，其余=1；NaN 一律按 0 兜底，F1.3）
```

① 硬/软过滤（+视觉软排除 AR-6：带图 + false → 排除；unknown → 保留、bias=0.25）
② 饱和剔除 → survivors；空 → 429 + retry-after（R2），例外见 §2
③ 粘性：health≥0.4 且 TTFT 未慢降(§3)；饱和/瞬态=绕行（不删绑定、照常续期 F1.1）
④ 首选：粘性命中 ? 粘性目标 : 按 effectiveWeight 加权随机（分流）
⑤ 失败续链：**按 effectiveWeight 确定性降序**（AR-7；相同分 tie-break=routeId 字典序，CHN-1 可断言）——
   首跳随机是分流，第二跳是抢救：既然已经失败一次，直奔剩余里最稳的，不再掷骰子。
   降序只影响同请求内的续链次序，不影响跨请求首跳分流——低权重候选仍有首跳流量，不缺样本。
⑥ 链预算 N10 / 4xx 短接（带图例外见 §4）/ §8-4 取消语义 全部不变。
⑦ **决策快照（F5.2）**：chainAttempts 每条附 pick 时刻全部幸存者的 `weight/health/speedFactor/effectiveWeight` 快照——线上诊断"为什么选了 B"的唯一手段，不做则 v2 不可运维。

## 6. 配置（F5.3 收敛：settings 只留 6 个，其余为常量）

```
autoSaturation:   { enabled: true, baseSec: 60, maxSec: 1800 }
autoSpeedFactor:  { enabled: true, floor: 0.5, cap: 2.0 }
```

常量（代码内定义，不进 settings）：`STICKY_SLOW_DEMOTE=3.0 / RESTICK=2.0`、`VISION_UNKNOWN_BIAS=0.25`、`VISION_LEARN_THRESHOLD=2`、`HEALTH_SAMPLE_RATE_LIMIT=1/min/vkey`、`EMA_ALPHA=0.3`、`MAX_SPEED_SAMPLES=256`。

### 回滚预案（R9）

三信号各有 `enabled` 开关，**每阶段可独立回滚**：关开关即回到 v1 行为，无需回滚代码。设置热读，改动即刻生效。

### 验收指标（F4.2，v2 的"变好了"判据）

日志已有 chainAttempts/attempts，零新增采集成本。上线前用 v1 跑基线一周，上线后对比同指标：
1. **跨候选失败率**：`attempts>1 的成功请求 / 成功请求`
2. **全链失败率**：所有候选耗尽的请求占比
3. **成功请求 p95 TTFT**（流式）
验收门槛：1、2 显著下降且 3 不劣化，否则关开关回滚并复盘。

### 显式不做清单（R10，防发散）

- 多臂老虎机 / 强化学习式路由（样本量撑不起，状态机足够）
- 按用户/部门分组路由策略（超出"个人管理台"定位）
- 成本感知因子（cost factor——现有 weight 已可人工表达价格偏好）
- 引入第三方熔断器库（自研三状态机已覆盖，引库得不偿失）

## 8. 新增回归钉

- SAT-1 连续 3×429 → 进入饱和；后续请求不选它
- SAT-2 retry-after > 退避值时取 retry-after 且突破 cap
- SAT-3 全候选饱和 → 直接 429 + retry-after=min(saturatedUntil)（不发必败请求）；剩余 <5s 的候选仍被尝试
- SAT-4 饱和期内一次成功 → 退避清零
- SAT-5 粘性目标饱和 → 本轮绕行、绑定保留且续期（degraded 标）
- SAT-6 单链单次 429（换 key 成功）→ 不触发饱和；60s 滑动窗跨 key ≥2 → 触发（F1.2）
- SAT-7 合成 429 顶层报错含「所有候选饱和」字样，与上游透传可区分（F2.2）
- SPD-1 factor 上下 clamp；SPD-2 冷启动 factor=1
- SPD-3 粘性慢降级（3×）与回粘（2×）迟滞
- SPD-4 样本滚出后 factor 衰减回 1，无硬跳变（F3.1）
- VIS-1 带图 + `supportsVision=false` → 软排除，粘性不覆写（同 tools 语义）
- VIS-2 导入已知多模态家族 → 初值 true；未知名 → unknown
- VIS-3 上游 400 命中视觉模式 + 次数门槛 → 自动置 false 持久化，链继续、不记健康样本
- VIS-4 用户手动标注后，学习不再覆盖；管理台可一键重置
- VIS-5 带图请求 inputEst 计入图片 token（data URL 精算 / http 常数）
- VIS-6 带图请求 unknown 候选 bias=0.25 后置
- VIS-7 带图 400 判定顺序：超窗 → 视觉 → C 格换候选，不短接（F2.1）
- STK-2 重粘 = 健康关 且 TTFT 关双过（F3.2）
- CHN-1 失败续链确定性：固定 rand 序列下第二跳可断言；tie-break=routeId
- CHN-2 chainAttempts 附决策快照（F5.2）
- AUTH-1 渠道全 key 401 → 候选记败恰一次
- OVF-1 全候选超窗 → 聚合报错文案
- SEC-1 健康样本 (routeId,vkey) 限频 1/min（F6.1）
- SEC-2 视觉学习需同候选 60s 内 ≥2 次独立命中（F6.2）
- NAN-1 pickWeighted 对 NaN 权重按 0 兜底，不毒化整体（F1.3）
