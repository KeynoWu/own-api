## 0. 设计主张

一句话：**健康分（坏没坏）、饱和态（忙不忙）、速度因子（快不快）是三个正交信号，各自独立窗口与状态机，最终在权重处相乘。**

v1 的问题：健康分一个信号被迫回答三个问题，答案是哪个都答不好——
- 慢但从不失败的候选 health≡1.0（"绕开慢的"宣传只有一半是真的）；
- 429 配额耗尽的候选 10 分钟后满血复活，每个窗口白烧一次失败请求；
- 粘性只看成功率，粘住一个首包劣化 5 倍的候选照样粘。

## 1. 挂：失败分类学（AR-1）

以两问过滤所有失败：**换候选能解决吗？**（错在候选还是请求）× **该惩罚健康吗？**（还会再犯吗）

| 格 | 判定 | 健康样本 | 处置 | 现状 |
| --- | --- | --- | --- | --- |
| A 候选真故障 | 错在候选，会再犯 | 记败 | 换候选/换 key 续链 | ✓（5xx/超时/连接拒绝/404 模型名） |
| B 候选暂时饱和 | 错在候选，**但会很快自愈** | **不记**（10min 窗会把尖峰错杀成长期劣化） | **饱和态**（§2） | 429 现仅换 key/候选 |
| C 请求×候选不匹配 | 候选没错 | 不记（sample:false） | 换候选续链 | ✓（超窗 C10 / 协议软过滤 / 视觉 §4） |
| D 请求本身坏 | 换谁都没用 | 不记 | 短接全链透传 | ✓（其它 4xx） |
| E 客户端取消 | — | 不记 | 双向剔除 | ✓（499 §8-4） |

**AR-2（G9 修正现状栏）**：渠道号池内所有 key 均鉴权失败（401/403）→ 渠道级真故障，对候选记**一次**健康败样本。~~现仅透传不记~~ **评审团证伪：现状已记**（gateway.ts:580 `sample=!lastWasRateLimit` → 真；e2e.ts:519 已有 fail===1 绿钉）——P0 该项收敛为补 AUTH-1 钉的多 key 形态（双 k-401 渠道，断言恰记 1 次且两 key 均冷却）。

**AR-3（C 格边角）**：全候选均超窗时，最终报错聚合为「所有候选窗口不足（最大 N tokens）」，不再透传最后一个候选的原始报错；chainAttempts 明细保留。

**F2.1（G2/G4 修订收窄）**：带图请求的 400 **仅在命中视觉保守模式列表（§4）时**按 C 格处理（候选可能只是不支持视觉，链继续）——其余 400 维持 D 格短接透传（防真·参数错误全链烧尽退化成 502 聚合、诱发 SDK 重试风暴、构造 16 倍请求放大面）。判定顺序固定：超窗（C10）→ 视觉模式命中（学习 + C 格续链）→ 其它 400（D 格短接，维持现状）。**通则（G3）**：链穷尽且全部失败属 invalid_request 类（无 429/5xx/超时混入）→ 顶层回 **400** + 聚合文案 + 最具体原文（不再是 502），同步修订 C17 基线钉为「混合失败 502；纯 4xx 聚合 400」。

## 2. 饱和态 saturation（AR-4，新增状态机）

- **触发（R1 修订 + F1.2 窗口定义）**：需满足其一，防单次尖峰误杀——
  (a) 该候选号池**所有可用 key** 在链内均 429（key 级冷却先行且已耗尽）；
  (b) **60s 滑动窗**内对同一候选**跨 key 累计 ≥2 次** 429（不以链为作用域）；**G7 前置条件：窗内对该候选零成功样本**（出现成功即清零计数）——绝对计数对高并发健康候选是系统性误杀（97% 成功率 ×100req/min 常态 2 次 429），并行 agent 秒级 2 连 429 同样误杀；**计数口径（G10）**：不同 key 各计 1 次，同 key 冷却到期后的重复 429 只计首值（key 级冷却已罚过）；已处于饱和期的探测 429 不入窗。
  单次 429 且换 key 成功 → 只走号池冷却，不触发候选饱和（避免与 key 级冷却双重惩罚）。
- 状态：`saturatedUntil: Map<routeId, until>`；时长 `min(base × 2^n, cap)`，`base=60s`、`cap=1800s`、n=该候选连续饱和次数。
- **retry-after 优先（F4.3 + G8 上限）**：上游显式给出 retry-after 时取 `max(retryAfter, 退避值)` 且不受 1800s cap 约束，但**设 24h 绝对上限**——pool.ts:102 实证过上游回 11.6 天 retry-after，无上限 + 无复位口 = 一个撒谎的响应头把候选移出存活集到进程重启。**复位口**：管理台加「清除饱和」按钮，`/auto-health/reset` 扩为四态复位（health/sticky/saturation/speed）。头解析容错：非数字/为 0 视同未给（G10：parseRetryAfter 需把 0/负归一 undefined，现状 '0' 解析为 0ms）。
- **清零**：只可能发生在全饱和回退路径（唯一会试饱和候选的路径）试出成功时。
- **生命周期（R5）**：进程内存态，与健康/粘性同生命周期，不持久化。
- **单调性（G11）**：重触发时 `saturatedUntil = max(旧值, 新值)`（n 照常递增）——retry-after 驱动的长饱和不得被后续 429 截短。
- 效果：饱和候选**移出存活集**（不参与首选与续链）；**空集三分支（G1，修 R2 空集归属冲突）**：全硬过滤 → 404（现状）；存在 saturatedUntil>now 的候选（无论是否同时被软排除——含「key 全冷却」瞬态）→ **429 + retry-after**；仅软排除 → 维持 404。合成 429 的 `retry-after = clamp(min(saturatedUntil)-now, 1s, 24h)`，**不经 retryAfterHeader**（其 cooldownMaxMs=900s 钳制会吃掉 F43 的突破语义；SAT-2 断言对象是响应头）；上游透传 429 维持既有钳制。例外：某候选剩余饱和期 < 5s 且剩余链预算 > max(5s, 单跳渠道超时) → 仍试它。
- **顶层报错可区分（F2.2）**：合成 429 的 message 固定为「所有候选饱和（最早 Xs 后恢复）」，与上游透传 429 区分；chainAttempts 照常带明细。
- **与粘性（F1.1 + G5/G6 机制衔接与作用域三分）**：饱和候选**保留在 evals 中且 transient=true、reason='saturated'**，仅从 survivors 数组移除——否则现有 bypass 分支（gateway.ts:897-900 读 evals[].transient）会误删绑定。**续期作用域三分**：① 饱和绕行 → 续期 + degraded 标（StickyEntry 增 degraded 字段，非绕行命中时清除转正；/auto-health 增 sticky[].degraded 出口，SAT-5 才可断言）；② TTFT 慢降粘（§3）→ 绕行**不续期**（TTL 到期后按重粘双条件重建，否则 2× 迟滞成死代码）；③ 结构性排除（tools/视觉）→ 绕行不续期（现状语义，让绑定自然过期重粘到可用候选——若泛化续期会永久锁死在不支持视觉的目标上）。
- 与健康的分工：健康只回答"坏没坏"；饱和只回答"现在忙不忙"。429 永远不进健康窗（C11 不变）。
- **样本污染防护（F6.1 + G12/G13 双视角会审修订）**：限频**仅施于失败样本**——每 `(routeId, vkey)` 每分钟至多 1 个失败样本，成功样本不限频（环形上限兜底）。按字面连成功一起限会反向放大污染：30RPM 诚实流量 10min 只记 10 成功 vs 攻击 1 败/min → health 恒 0.5。配套：`health()` 把 total<3 守卫提到 ok==0 分支前（单败样本不降 0.1，维持成本抬到 ≥2 败/10min）；recordAttempt 增 vkeyId 参数（onSample 两处闭包均有 vkey 在作用域）；限频器挂 clearHealthFor 既有删除钩子；**既有钉冲突**：fail:3 断言钉 / 冷启动钉 / 迟滞松手钉需按新口径修订，限频器加测试清口。
- 观测（R8 补全）：`/auto-health` 增 `saturatedUntil / speedFactor / ownTTFTP50 / ownThroughputP50 / bench`；管理台号池健康页展示饱和剩余秒数与速度因子。
- 开放问题：503 且带 retry-after 是否同样进饱和态？v1 暂不（保持 429 单一触发源），观察一个版本。

## 3. 速度因子 speedFactor（AR-5）

**测什么（R3 修订——指标分工，纠正可比性污染）**：
- **权重层用 decode 吞吐**：`completionTokens / 生成耗时`，与输入输出长度基本无关——最公平的跨候选指标。端到端时延是陷阱：话痨模型、接长文档的候选、吃缓存的候选（prefill 短 → TTFT 天然好看）都会被系统性误判。
- **粘性降级判据用 TTFT**：它才是用户体感（等首包）。粘性目标是"这个用户此刻的体验"，允许有偏。
- **两个指标、两个基准，不混用**（实现时不得共用一个字段）。
- **样本必须按 attempt 采集（G14，禁止链级污染）**：gateway 现有 ttftMs/latencyMs 对 attempts>1 是链级污染值（含前序失败候选全部耗时，DR-SI-5 明令排除、buildSpeedStats 已实现剔除）——v2 若照抄会把被污染值灌进权重与粘性，系统性压低最稳候选。attemptRoute 内计时基准从 ctx.t0 改为本次 attempt 起点（aT0），per-attempt 耗时/token 落 chainAttempts 扩展字段。**准入条件（G15）**：流式且 completionTokens≥16（废掉 max_tokens=1 + 巨 prefill 的吞吐毒样本）；权重层只采流式样本，非流式仅入观测。
- **非流式口径（F3.3）**：非流式无首包，吞吐 = `completionTokens / 总时延`——含 prefill 污染，是下界近似；文档标注该误差，跨流式/非流式不互比。

**跟谁比**：相对基准，不用绝对阈值（50k 上下文 prefill 慢是物理性的）。
- 基准 = **速度样本 ≥3 的候选**同指标 p50 的中位数（G17：不含冷启动候选——否则 median(0,0,100)=0 把全体压到 floor 且无 NaN 兜底）；无任何合格候选 → 全体 factor=1。auto.ts 内部轻量维护，**5s 计算缓存**（不逐请求扫全量）；注意 DR-SI-9 现实现是全样本全局 p50（usage.ts:313-317），与此公式不同，不得照抄。
- `speedFactor = clamp(bench / own_p50, 0.5, 2)`——**clamp 必须有**：否则一个快候选垄断全部流量。
- **样本窗与平滑（R3 + F3.1/F3.4）**：速度窗 **1h**（慢不需要秒级反应，与健康的 10min 窗刻意不同）+ **EMA（α=0.3）**。样本滚出窗口时**不做硬重置**：沿用上一次有效因子、按 1h 半衰期指数衰减回 1——否则低权重候选陷入"流量少→样本滚出→factor 硬回 1→流量回流→样本变差→再降权"的约 1h 周期振荡。
- **样本上限（F1.4）**：速度样本同款环形上限（MAX_SPEED_SAMPLES=256/候选），与健康窗对齐。
- 冷启动（速度样本 <3）：factor = 1.0，与 health 冷启动口径一致。

**怎么用（三个注入点，强度递增）**：
1. **权重层**（P2）：并入统一有效权重（§5 R4）——慢候选软降权，流量自然漂移，不剔除。
2. **粘性层**（P2 + G16 基准修正）：粘性保持条件从 `health ≥ 0.4` 扩为 `health ≥ 0.4 且 TTFT_p50 < 3 × 自身基线`；降粘后重粘需 `< 2 ×`——与 C3 同构的迟滞带（3×/2×）。**基准是候选自身近期 TTFT 漂移（自身历史 p50 的 EMA），不是跨候选绝对比值**——跨候选绝对基准会把推理型模型（TTFT 天然高但稳定）永久降粘，偏离 §0 自定义的「劣化」问题（慢=变差，不是慢=比别人慢）；样本不足（<3）→ 视为未慢降。重粘判定 = 健康关 **且** TTFT 关双过（F3.2）。
3. **对冲层**（并入 AR-5，**明确暂缓**）：TTFT 超阈值向第二候选发对冲请求，先首包者胜。计费语义（对冲请求可能双边计费）未想清前不做，仅留接口位。

## 4. 视觉能力三态（AR-6，新增）

**问题**：加路由要不要人工标注多模态？纯自动识别不可靠（OpenAI/Anthropic `/models` 均无能力字段；模型名启发式对内部部署模型失灵；主动探测花钱且部分网关静默丢图返回 200，探测结果反而造假）。纯手动又违背"开箱即用"。

**方案：三态标注 + 启发式初值 + 被动降级学习。**

- 路由 schema 增 `supportsVision?: boolean` 三态：`true / false / unknown`（unknown ≠ 支持，只是没证据）。
- **启发式初值**：从上游导入模型时按已知多模态家族静态表（gpt-4o/4.1、o 系列、claude-3+、gemini、glm-4v、qwen-vl、llava、llama-3.2-vision…）置 `true`，其余 `unknown`；表只做先验，可配置关闭。
- **① 硬过滤扩展**：请求含图片块（OpenAI `image_url` / Anthropic image）且候选 `supportsVision === false` → 软排除（与 tools/流式同语义：绕行不改写粘性）。`unknown` → 放行，交给学习闭环兜底。
- **可选加权**（实现细节，默认开）：带图请求时 `unknown` 候选的 visionBias=0.25（§5 统一权重），非排除——尽量不付"第一次失败"的学费。
- **被动降级学习（关键闭环，R6 收窄 + F6.2/G18 指纹门槛）**：仅当「请求确实含图 + 上游 400 + 报错命中**保守白名单**（仅能力声明类文案，显式排除单图处理失败类：could not process / invalid media type / image too large / unsupported format）+ **同候选命中 ≥2 个不同图片内容指纹**（data URL SHA-256 截断；防粘性+重试两连击同一张坏图造成永久误标）」齐备才触发 → 自动置 `false` 并持久化、日志记一条、链继续（C 格语义）；学习动作加每候选 1h 冷却。**用户手动改过的路由学习不再覆盖**；管理台可**一键重置回 unknown**。
- **判定顺序（F2.1）**：带图 400 的处理次序固定：超窗（C10）→ 视觉学习 → 按 C 格换候选。视觉永不与 C10/D 格双重判定。
- **管理台可见**：路由行展示视觉 ✓ / ✗ / 未知，可手动修改。
- **配额精度顺带修（R7 补坑）**：带图请求的 `inputEst` 计入图片 token——data URL 可解析出 w×h 精算（≈(w×h)/750）；**http URL 不为计费去下载图片**，用保守常数（1000 tokens/图）。现状图片请求预占偏低，限额用户被低估占用。
- **不做**：音频/PDF 独立字段（转换层 audio 已丢弃+告警；PDF 留接口）；主动探测请求。

## 5. 决策管线 v2

**R4 统一：全系统唯一有效权重公式**（首选随机、续链降序、unknown 后置共用一处实现）：

```
effectiveWeight = weight × health × speedFactor × visionBias
                  （visionBias：带图请求 unknown=0.25，其余=1；NaN 一律按 0 兜底，F1.3）
```

① 硬/软过滤（+视觉软排除 AR-6：带图 + false → 排除；unknown → 保留、bias=0.25）
② 饱和剔除 → survivors；空 → 三分支（G1，见 §2）：全硬过滤 404 / 含饱和 429+retry-after / 仅软排除 404
③ 粘性：health≥0.4 且 TTFT 未慢降(§3)；饱和/瞬态=绕行（不删绑定、照常续期 F1.1）
④ 首选：粘性命中 ? 粘性目标 : 按 effectiveWeight 加权随机（分流）
⑤ 失败续链：**按 effectiveWeight 确定性降序**（AR-7；相同分 tie-break=routeId 字典序，CHN-1 可断言）——
   首跳随机是分流，第二跳是抢救：既然已经失败一次，直奔剩余里最稳的，不再掷骰子。
   降序只影响同请求内的续链次序，不影响跨请求首跳分流——低权重候选仍有首跳流量，不缺样本。
⑥ 链预算 N10 / 4xx 短接（带图例外见 §4）/ §8-4 取消语义 全部不变。
⑦ **决策快照（F5.2 + G19 三层扩展）**：chainAttempts 每条附三层——`pick: 'sticky'|'weighted'|'chain'`（复盘"怎么来的"）；`survivors: [{routeId, weight, health, speedFactor, visionBias, effectiveWeight, sampleCount}]`（为什么选它）；`excluded: [{routeId, kind: 'hard'|'soft'|'saturated'|'vision', reason}]`（为什么没考虑它——理由 evaluateCandidates 已产出零成本）。链内权重/健康/速度一律用首跳评估时快照（与 CHN-1 断言同源，接受链内时滞，写死不取实时值）。不做则 v2 不可运维。

## 6. 配置（F5.3 收敛：settings 只留 6 个，其余为常量）

### 回滚预案（R9）

三信号 + 视觉各有 `enabled` 开关，**饱和/速度/视觉三阶段可开关回滚**；P0 的 AR-7（确定性降序）与 F6.1（限频）无开关、回滚 = 回退版本（G20：原"每阶段"表述过宽，按此收窄）。设置热读，改动即刻生效。

### 验收指标（F4.2，v2 的"变好了"判据）

日志已有 chainAttempts/attempts。**G21 修正三个坑**：① 基线周前把 `logRetention` 提到 200000（默认 2000 撑不满一周，后半周被静默裁掉）；② 指标 1 口径改用 `chainAttempts.length>1`（attempts 混入 key 级重试，单候选换 key 成功会被误计"跨候选失败"）；③ buildStats/buildSpeedStats 加 from/to 参数（现只有 rangeHours 尾窗，无法以部署时刻为界对比）。指标：
1. **跨候选失败率**：`chainAttempts.length>1 的成功请求 / 成功请求`
2. **全链失败率**：所有候选耗尽的请求占比
3. **成功请求 p95 TTFT**（流式）
验收门槛（G21 量化）：1、2 相对降幅 ≥30% 且绝对差 ≥1 个百分点，且 3 不劣化；周样本 <100 则该周作废顺延。否则关开关回滚并复盘。

### 显式不做清单（R10，防发散）

- 多臂老虎机 / 强化学习式路由（样本量撑不起，状态机足够）
- 按用户/部门分组路由策略（超出"个人管理台"定位）
- 成本感知因子（cost factor——现有 weight 已可人工表达价格偏好）
- 引入第三方熔断器库（自研三状态机已覆盖，引库得不偿失）

## 8. 新增回归钉

- SAT-1（G22 文案修正）双 k-429 key 渠道单链内两 key 均 429 → 触发 (a) 进入饱和；后续请求不选它（单 key 渠道造不出该序列——首败即冷却 30s，第二发在 ① 被软剔）
- SAT-2 retry-after > 退避值时取 retry-after；**断言对象是 HTTP 响应头**且不受 cooldownMaxMs 钳制（合成 429 独立构造，G3/G14）；mock 需第四开关可控 retry-after（含大值/0/非数字形态）
- SAT-3 全候选饱和 → 直接 429 + retry-after=min(saturatedUntil)（不发必败请求）；剩余 <5s 的候选仍被尝试
- SAT-4 饱和期内一次成功 → 退避清零
- SAT-5 粘性目标饱和 → 本轮绕行、绑定保留且续期（degraded 标，断言 /auto-health 的 sticky[].degraded 出口 + 恢复转正半段）
- SAT-6 单链单次 429（换 key 成功）→ 不触发饱和；60s 滑动窗跨 key（不同 key 各计 1）≥2 → 触发；窗内出现成功样本 → 计数清零（G7）；同 key 冷却后重复 429 不重计（G10）
- SAT-8 saturatedUntil 单调性：长 retry-after 饱和期内再次 429 不得缩短 until（G11）
- SAT-7 合成 429 顶层报错含「所有候选饱和」字样，与上游透传可区分（F2.2）
- SPD-1 factor 上下 clamp；SPD-2 冷启动 factor=1
- SPD-3 粘性慢降级（3×）与回粘（2×）迟滞
- SPD-4 样本滚出后 factor 衰减回 1，无硬跳变（F3.1）
- VIS-1 带图 + `supportsVision=false` → 软排除，粘性不覆写（同 tools 语义）
- VIS-2 导入已知多模态家族 → 初值 true；未知名 → unknown
- VIS-3 上游 400 命中视觉白名单 + ≥2 个不同图片指纹 → 自动置 false 持久化，链继续、不记健康样本（G18）
- VIS-8 带图请求的真·参数错误 400 → 维持 D 格短接（F2.1 收窄，G2）；全候选纯 4xx 耗尽 → 顶层 400 聚合（G3）

## 10. 评审团裁决摘要（G 系列）

**独立证实（关键 major）**：
- G1 R2 空集归属冲突：key 全冷却时候选在 ① 就被软剔，R2 的 429 走不到 → 空集三分支裁决
- G2/G4 F2.1 无停损（两视角独立同向）：真参数错误带图 400 全链烧尽 → 502 回归 + SDK 重试风暴 + 16 倍放大 → 视觉模式命中才 C 格 + 纯 4xx 耗尽回 400
- G12/G13 F6.1 连成功样本一起限会反向放大污染（30RPM 诚实流量被 1 败/min 打成恒 0.5）→ 仅限失败样本 + 单败不降 0.1
- G7 饱和触发(b) 绝对计数误杀高并发健康候选 → 零成功前置 + 跨 key 计数定义
- G14 速度样本复用链级 ttftMs/latencyMs 违反 DR-SI-5 → per-attempt 采集
- G8 F4.3 无上限 retry-after（pool.ts 实证过 11.6 天）→ 24h 绝对上限 + 复位口
- G16 粘性 TTFT 跨候选绝对基准会永久降粘推理型模型 → 改自身基线漂移
- G18 视觉学习"60s×2 独立链"防不了同图两连击、又在单 vkey 形态难触发 → 改 ≥2 个不同图片指纹

**证伪的自我结论（如实记录）**：
- AR-2 现状栏错误：渠道全 key 401 今天已记健康败样本（gateway.ts:580），非"仅透传不记"
- R7 前提以偏概全：现状图片预占 1600 tok/图，"普遍偏低"不成立；http 常数 1000 反而更不保守 → 改为上界口径 ≥1600
- "既有钉全数不破"结论错误：F6.1 按字面会破 3 个既有 e2e 钉

**新发现的横向缺口**：四个时间常量全部无注入点（时钟侧测试基建缺失）；新内存态缺 clearHealthFor 式删除钩子；验收基线在 logRetention=2000 下无数据可算。
