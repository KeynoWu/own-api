# auto 路由 v2 设计：三信号正交（健康 / 饱和 / 速度）+ 视觉能力

> 状态：设计稿（待评审）
> 前置：speed-insights v1.1（DR-SI 系列）已提供 TTFT/吞吐采样与单源基准
> 本文决策编号 AR-xx；沿用既有回归钉（C3/C10/C11/C12/N10/§8-4/N11）

## 0. 设计主张

一句话：**健康分（坏没坏）、饱和态（忙不忙）、速度因子（快不快）是三个正交信号，各自独立窗口与状态机，最终在权重处相乘。**

v1 的问题：健康分一个信号被迫回答三个问题，答案是哪个都答不好——
- 慢但从不失败的候选 health≡1.0（"绕开慢的"宣传只有一半是真的）；
- 429 配额耗尽的候选 10 分钟后满血复活，每个窗口白烧一次失败请求；
- 粘性只看成功率，粘住一个首包劣化 5 倍的候选照样粘。

## 1. 挂：失败分类学（AR-1）

以两问过滤所有失败：**换候选能解决吗？**（错在候选还是请求）× **该惩罚健康吗？**（还会再犯吗）

| 格 | 判定 | 健康样本 | 处置 | 现状 |
| --- | --- | --- | --- | --- |
| A 候选真故障 | 错在候选，会再犯 | 记败 | 换候选/换 key 续链 | ✓（5xx/超时/连接拒绝/404 模型名） |
| B 候选暂时饱和 | 错在候选，**但会很快自愈** | **不记**（10min 窗会把尖峰错杀成长期劣化） | **饱和态**（§2） | 429 现仅换 key/候选 |
| C 请求×候选不匹配 | 候选没错 | 不记（sample:false） | 换候选续链 | ✓（超窗 C10 / 协议软过滤 / 视觉 §4） |
| D 请求本身坏 | 换谁都没用 | 不记 | 短接全链透传 | ✓（其它 4xx） |
| E 客户端取消 | — | 不记 | 双向剔除 | ✓（499 §8-4） |

**AR-2（A 格边角）**：渠道号池内所有 key 均鉴权失败（401/403）→ 这是渠道级真故障，对候选记**一次**健康败样本（现仅透传不记）；单 key 失败仍只走号池冷却，不记。

**AR-3（C 格边角）**：全候选均超窗时，最终报错聚合为「所有候选窗口不足（最大 N tokens）」，不再透传最后一个候选的原始报错；chainAttempts 明细保留。

## 2. 饱和态 saturation（AR-4，新增状态机）

- 触发：候选在单次链内发生 429（无论该 429 来自 key 还是渠道级；key 级冷却照旧先行）。
- 状态：`saturatedUntil: Map<routeId, until>`；时长 `min(base × 2^n, cap)`，`base=60s`、`cap=1800s`、n=该候选连续饱和次数；**任一成功请求清零**。
- 若上游 429 带 `retry-after`：取 `max(retryAfter, 退避值)`。
- 效果：饱和候选**移出存活集**（不参与首选与续链）；**若存活集因此为空** → 回退到饱和集，按「最早醒来」排序续链——宁可排队试一下，也不直接 502。
- 与粘性：粘性目标饱和 → 同 C6 瞬态语义：本轮绕行、**不删绑定**（它会回来）。
- 与健康的分工：健康只回答"坏没坏"；饱和只回答"现在忙不忙"。429 永远不进健康窗（C11 不变）。
- 观测：`/auto-health` 增 `saturatedUntil`；管理台号池健康页展示剩余秒数。
- 开放问题：503 且带 retry-after 是否同样进饱和态？v1 暂不（保持 429 单一触发源），观察一个版本。

## 3. 速度因子 speedFactor（AR-5）

**测什么**：流式请求取 **TTFT p50**，非流式取**端到端 p50**——两者都与输出长度无关（端到端绝对时延是陷阱：话痨模型被错杀）。样本随 `recordAttempt` 顺带采集（gateway 已有 ttftMs / latencyMs）。

**跟谁比**：相对基准，不用绝对阈值（50k 上下文 prefill 慢是物理性的）。
- 基准 = 全候选 TTFT p50 的中位数（DR-SI-9 同源思想），auto.ts 内部轻量维护，**5s 计算缓存**（不逐请求扫全量）。
- `speedFactor = clamp(bench / own_p50, 0.5, 2)`——**clamp 必须有**：否则一个快候选垄断全部流量。
- 冷启动（速度样本 <3）：factor = 1.0，与 health 冷启动口径一致。

**怎么用（三个注入点，强度递增）**：
1. **权重层**（P2）：有效权重 = `weight × health × speedFactor`——慢候选软降权，流量自然漂移，不剔除。
2. **粘性层**（P2）：粘性保持条件从 `health ≥ 0.4` 扩为 `health ≥ 0.4 且 own_p50 < 3 × bench`；降粘后重粘需 `own_p50 < 2 × bench`——与 C3 同构的迟滞带（3×/2×）。
3. **对冲层**（并入 AR-5，**明确暂缓**）：TTFT 超阈值向第二候选发对冲请求，先首包者胜。计费语义（对冲请求可能双边计费）未想清前不做，仅留接口位。

## 4. 视觉能力三态（AR-6，新增）

**问题**：加路由要不要人工标注多模态？纯自动识别不可靠（OpenAI/Anthropic `/models` 均无能力字段；模型名启发式对内部部署模型失灵；主动探测花钱且部分网关静默丢图返回 200，探测结果反而造假）。纯手动又违背"开箱即用"。

**方案：三态标注 + 启发式初值 + 被动降级学习。**

- 路由 schema 增 `supportsVision?: boolean` 三态：`true / false / unknown`（unknown ≠ 支持，只是没证据）。
- **启发式初值**：从上游导入模型时按已知多模态家族静态表（gpt-4o/4.1、o 系列、claude-3+、gemini、glm-4v、qwen-vl、llava、llama-3.2-vision…）置 `true`，其余 `unknown`；表只做先验，可配置关闭。
- **① 硬过滤扩展**：请求含图片块（OpenAI `image_url` / Anthropic image）且候选 `supportsVision === false` → 软排除（与 tools/流式同语义：绕行不改写粘性）。`unknown` → 放行，交给学习闭环兜底。
- **可选加权**（实现细节，默认开）：请求带图时 `unknown` 候选排到已知 `true` 候选之后（乘一个降序偏置，非排除）——尽量不付"第一次失败"的学费。
- **被动降级学习（关键闭环）**：上游 400 且报错命中「视觉不支持」模式 → 自动置 `false` 并持久化、日志记一条、链继续（C 格语义：候选没错，不记健康样本）。**用户手动改过的路由学习不再覆盖**——人的标注永远赢。
- **管理台可见**：路由行展示视觉 ✓ / ✗ / 未知，可手动修改。
- **配额精度顺带修**：带图请求的 `inputEst` 计入图片 token（OpenAI 口径 ≈ (w×h)/750）——现状图片请求配额预占偏低，限额用户被低估占用。
- **不做**：音频/PDF 独立字段（转换层 audio 已丢弃+告警；PDF 留接口）；主动探测请求。

## 5. 决策管线 v2

```
① 硬/软过滤（+视觉软排除 AR-6；带图时 unknown 后置偏置）
② 饱和剔除 → survivors；空则回退饱和集（按最早醒序）
③ 粘性：health≥0.4 且 未慢降(§3)；饱和/瞬态=绕行（不删绑定）
④ 首选：粘性命中 ? 粘性目标 : 加权随机(weight × health × speedFactor)
⑤ 失败续链：**确定性降序**（按 health × speedFactor × weight，AR-7）——
   首跳随机是分流，第二跳是抢救：既然已经失败一次，直奔剩余里最稳的，不再掷骰子
⑥ 链预算 N10 / 4xx 短接 / §8-4 取消语义 全部不变
```

## 8. 新增回归钉

- SAT-1 连续 3×429 → 进入饱和；后续请求不选它
- SAT-2 retry-after > 退避值时取 retry-after
- SAT-3 全候选饱和 → 选最早醒者续链，不 502
- SAT-4 饱和期内一次成功 → 退避清零
- SAT-5 粘性目标饱和 → 本轮绕行且绑定保留（同 C6 语义）
- SPD-1 factor 上下 clamp；SPD-2 冷启动 factor=1
- SPD-3 粘性慢降级（3×）与回粘（2×）迟滞
- VIS-1 带图 + `supportsVision=false` → 软排除，粘性不覆写（同 tools 语义）
- VIS-2 导入已知多模态家族 → 初值 true；未知名 → unknown
- VIS-3 上游 400 命中视觉不支持模式 → 自动置 false 持久化，链继续、不记健康样本
- VIS-4 用户手动标注后，学习不再覆盖
- VIS-5 带图请求 inputEst 计入图片 token
- VIS-6 带图请求 unknown 候选后置于已知 true 候选
- CHN-1 失败续链确定性：固定 rand 序列下第二跳可断言
- AUTH-1 渠道全 key 401 → 候选记败恰一次
- OVF-1 全候选超窗 → 聚合报错文案
- 既有 C3/C10/C11/C12/N10/N11/§8-4 全数不破
